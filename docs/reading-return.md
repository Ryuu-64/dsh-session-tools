# 创建卡片返回阅读位置

关联 https://github.com/Ryuu-64/dsh-session-tools/issues/20 。这份实现仍需真实宿主验收，不是完成声明。

## 实现边界

- 复用 DSH 0.2.0-rc.2 的 `uiWorkspace.openSession`、Session 引用和 `loadThrough`。不替换 Chat、不改宿主、不调用 `Session.cancel`。
- 创建卡片只接受成功结果中的可信 `meta.sessionId`。点击时从该卡片所在的原生主阅读区捕获会话、内容节点、分片标识、段落顺序和可见偏移。相同文本不用于搜索目标。
- 目标预加载成功、同一主阅读区确认选中目标后，才提交一个返回点。失败及重复打开当前会话保留旧返回点；B 到 C 替换为离开 B 的位置。
- 返回先使用只读临时引用确认来源可访问并加载所需历史。来源内容不存在时不导航。引用在完成、失败或取消后释放，主阅读区的引用仍由 UIWorkspace 拥有。
- 返回成功需要找到原内容、完成真实滚动采样并确认偏移。失败显示原因并保留重试入口，不把顶部或近似内容当作成功。每次等待最多 15 秒。
- 用户滚动、键盘阅读、新导航、刷新或插件卸载会取消本次恢复的界面效果。迟到的共享加载不会再次导航或抢焦点。不会改草稿、发消息、创建替代会话或取消归档。

## 必须继续验证的部分

- 当前页面适配器只辨认 RC2 的原生主阅读 occurrence。嵌入阅读区没有可定向导航的公开入口；从嵌入卡片仍可正常打开目标，但明确提示尚不能原位返回。不能据此把 Issue 的多阅读视图验收删掉。
- 独立滚动的折叠步骤组尚未纳入原位恢复；识别到这种来源时不创建返回点。展开布局可使用稳定的节点分片标识。
- 旧版宿主保留原创建卡片跳转，不声称拥有 RC2 的阅读返回能力。版本声明未扩大到 alpha，也未修改包版本或发布 npm。
- 正文已加载窗口全量挂载；需要验收历史补载、段落挂载、布局变化和流式增长，不能把它当成正文虚拟列表。
- 真实浏览器必须检查长会话、分页、重复段落、失败重试、来源删除、连续跳转、原位置成功确认、多窗口、同一会话多视图、用户主动滚动取消及卸载清理。

## 宿主接口边界

RC2 的 `ChatScrollPosition`、`chatScroll.read/save` 是公开类型，但回调只注入 Chat，并按 session 保存采样缓存。写缓存不命令当前界面恢复；`openView` 的 focus 也不被 Chat 消费。本实现没有将这些回调冒充即时 capture/restore API。

如果原生 Chat 的滚动拥有权使 DOM 适配无法可靠恢复，最小宿主方案应提供每个阅读 occurrence 的即时捕获与带取消信号的精确恢复入口，并返回“精确成功／内容缺失／被用户打断”的结果。宿主应继续拥有历史加载、follow-tail、分页保留锚和焦点的协调；插件只保存一次跳转关系。是否需要此改动，必须以真实浏览器失败证据确认。

## 验证入口

- `npm run check`：原有真实 SDK/宿主测试、卡片可信身份和新状态机／DOM边界测试。DOM边界测试的几何及传输是脚本边界，不代替真实 Chat 验收。
- `Reading return RC2` 工作流：安装精确官方 RC2 包树、将当前插件打包安装到临时 Web profile、通过官方 Session/JSONL 构造合成历史，再用 Chromium 操作真实 UI。无模型调用，不使用用户的 profile 或凭据。结果、截图和经过令牌清理的日志存入 CI artifact。
